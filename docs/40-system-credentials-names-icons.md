# 系统账号配置、名称与图标

2026-11-27完成本轮源码改造。保留麒麟原系统密钥环，不实施此前讨论的本地密钥替代方案。本轮不安装或替换用户正在运行的客户端，不发布自动更新，不部署后台。

## 账号配置

在现有配置机制中启用四个系统，入口统一位于各自工作台标题右侧“账号配置”。继续使用系统安全存储按systemId独立加密，状态接口只返回已配置标志和账号，不返回密码。验证码、证书口令、PIN和提交动作仍由原站流程处理。账号配置不能代替原系统实际鉴权。

| 系统 | 登录路径 | 字段依据与边界 |
| --- | --- | --- |
| 深圳市房屋租赁 | `/fwzl/LEAP/Login/4403/ZIBNEW/Login.html` | 原HAR不含登录HTML；一次匿名公开请求超时，采用标准账号name/id/autocomplete/placeholder及可见password输入的保守匹配。真实站点填充尚待核对。 |
| 深圳市一窗综合 | `/Accept/login` | 原HAR确认账号`#uname`、密码`#password`；不填CA口令`#capassword`及图形/短信验证码。 |
| 深圳一体化 | `/cas/login` | 原账号页确认`#username`、`#passwordVal`，原明文密码框在填入前掩码；不填密钥页`#pinCode`或隐藏加密结果`#casPd`。 |
| 全员人口 | `/login` | 原客户端在用自动填表代码确认`#username`、`#password`；不填`#authcode`。业务接口仍维持原未接入状态。 |

食药监现有材料为CA证书口令，广东人社为二维码门户，特种设备缺当前SSO登录HTML，均未冒充为已确认的普通账号密码表单。已有其他系统配置能力继续沿用。

填充要求精确源地址、声明登录路径、同form且可见的成对字段。SPA登录路由在观察回调内也重新核对；动态切换账号页时监听class/style/hidden/type/disabled变化。对声明登录路径的页面，每5秒重新尝试本地DOM填充，兼容用户完成密钥阶段后才显示账号表单的情况，不发出额外登录请求、不点击按钮、不覆盖用户已编辑的内容。

配置面板增加读取和保存状态、提交期间禁用及系统切换代次保护，清空已提交的密码输入，支持Enter保存。跨系统保存串行写入，关闭应用等待保存队列完成，避免覆盖其他账号。保存按钮使用“保存并打开原系统”，不错误暗示会强制退出已登录页面。

## 显示名称

| systemId | 应用名称clientName | 后台名称name |
| --- | --- | --- |
| shenzhen-housing-rental | 深圳市房屋租赁 | 深圳市房屋租赁备案登记管理系统 |

两个共享目录分别保存应用短名和后台全称。后台启动时仅将这两个ID的已知旧默认名称更新为新全称；管理员自定义名称保持原值。系统/事项ID、分区、账号配置键、授权、激活码、设备和历史记录均保持原身份，无需重发授权。

## 原站图标

一窗综合、深圳一体化及危化品使用已核对的原站静态标识，本地随包加载。来源、字节摘要和原图显示方式见`src/renderer/src/assets/system-icons/README.md`。缺少独立原站标识时，使用住房、人口、药品、特种设备、人社等业务图形，不将回退图形称为官方Logo。

侧边栏、工作台卡片、组件列表和原系统标签页共用SystemIcon，尺寸由使用位置控制；图片加载失败回退业务图形。业务图标不依赖原站在线或登录状态。
