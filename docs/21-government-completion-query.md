# 政务综合信息办结日期查询与新办排水许可内容

## 日期参数依据

用户于2026-11-03提供 `10.200.96.11.har`，其中 `ecs_searchAll` 请求（`name=laam_ex_sb`、`pageModule=ecs_queryAll`）按以下参数查询，响应HTTP 200：

```json
[
  { "name": "bj_bjsj", "value": "2026-10-01", "flag": 16, "sqlType": 93 },
  { "name": "bj_bjsj", "value": "2026-11-03", "flag": 17, "sqlType": 93 }
]
```

两个范围条件使用同一个字段 `bj_bjsj`，区别是起始条件的flag为16、截止条件为17，且两者都必须带 `sqlType:93`（JDBC TIMESTAMP）。不是 `sbsj`（申办时间），也不是 `fdbjsj`（法定办结时间）。不把会话请求头、原业务明细或完整HAR复制到项目、日志或测试夹具。

全部18个政务事项共用同一查询实现，将上述两个完整条件传入既有导出接口的查询对象；加密、RPC方法、后续详情补全及事项分类规则保持。原页面样本的排序仍为 `sbsj desc`，因此本次仅改变过滤条件，不擅自改变排序或工作表字段次序。

1.0.10首次实现遗漏了两个条件的sqlType，脱敏检查及测试也仅比较name/value/flag，未覆盖这一必需属性，导致实网导出HTTP200空响应。1.0.11修复补齐类型并让HAR对照比较原始日期条件的完整对象。实网只读对照确认：旧申办日期条件成功，漏类型的办结条件返回空响应，只有增加pageModule仍失败，补齐sqlType后成功；下载解析出687条受支持记录，办结日期均在2026-10-01至2026-11-03范围内。未查询企业付费接口、未保存业务明细或改写本地业务库。对照报告见 `private/diagnostics/government-export-20261103/`。

应用保留内部通用 `startDate` / `endDate` 键，便于继续保存批次时间段和命名导出文件；界面明确标为“办结开始日期”与“办结截止日期”，并要求提供完整有效范围。原始导出列14映射为 `approveDate`，实际含义为办结日期；本地再按这一列校验起止边界，排除范围外、缺失或无效办结日期，避免跨期混入数据。不以申办时间、证件制证时间或许可决定日期替代办结时间。

登录校验仍沿用此前实测有效的一行只读列表协议，独立保留其原有条件，避免业务日期调整改变登录识别。

>

本次改动用于后续重新查询/回流的数据，不批量改写既有台账或历史批次快照。旧批次需要按相应办结日期范围重新回流以生成采用新规则的结果。未变更原归集项目或线上部署。
