# 深圳一体化与F12本地测试版1.1.15

2026-11-27完成本地测试实现。业务代码提交 `28d1e93`，所有系统F12提交 `ab96ef2`。本次没有发布自动更新、部署后台或调整生产授权。

## 已实现

- 深圳一体化由目录占位改为实际插件，仍保留原10个事项ID、名称和授权范围。
- 默认本月接收时间，可选择接收、受理、办结时间，发送14位自然日起止参数；只使用原站全部经办列表，按公共事项码和明确名称过滤，不混入个人已办或其他事项。
- 逐笔采集完整办理过程，有流程号用`ywlsh`，无流程号用`lsh`。不按办件日期再次裁剪历史，不要求日志有独立ID，也不删除合法重复操作。
- 分别保留操作人、审批人、接收/操作/审批/完成/公示时间、环节、意见、原始及显示结果和撤回标志。列表和任务批次均可查看过程；Excel有“办件列表”“办理记录”两张工作表。
- 用户选择保留社保和岗位两个入口。它们共用原站合并事项和一份规范台账，授权、任务输出及审计仍按用户选择的入口；全局台账不重复存两份。只授权岗位入口时不能直接请求未授权的社保入口，查看、导出、版本历史均验证此边界。
- 单案过程读取失败保留办件并标记待补齐，已有历史保留且明确为上次记录；成功返回空数组才表示确实没有过程。取消、登录失效和限流及时停止，未确认成功的读取不会伪造成完整过程。
- 所有该系统请求串行，无固定2秒等待；请求与响应体超时合计最多5次尝试，其他错误不连续重试。
- 真实身份接口校验后才显示已登录，令牌及所需原站sessionStorage在主进程加密保存。识别CAS和业务登录页；恢复成功后打开原站首页。没有自动提交PIN或账号密码。
- 所有原系统标签页、公示平台和工作台支持F12打开独立开发者工具；有当前原系统时优先定位该页面，重复按键复用已有窗口，关闭标签页后不误开隐藏页面。

## 证书与持久化

1.1.14的证书兼容最初作用于原站WebContents。1.1.15还覆盖主进程恢复会话时的`session.fetch`：仅在深圳独立分区配置了唯一已审核源地址时，校验固定叶证书DER指纹、SAN和有效期，放行名称不匹配。Chromium的会话回调只有主机名，应用查询固定到已声明8001端口；原页面的完整URL例外继续保留。其他错误、变更证书和其他分区不放行。

分别使用Electron44原生fetch、Electron22兼容fetch，从空白隔离分区、未打开任何原站标签页进行一次无凭据身份接口请求，均成功完成TLS并得到HTTP200、业务码1。此结果只证明冷启动API通道能连接且未登录结果未被当成已登录，不代表带用户凭据的真实回流验收。

原站叶证书有效期到2026-12-12，换证后需重新审核更新内置指纹。未关闭全局证书检查或安装系统证书。
