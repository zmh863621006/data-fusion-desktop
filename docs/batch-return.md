# 多业务回流与系统队列

多事项的一键回流系统可在现有开始按钮旁打开“批量回流”。面板带入当前日期，按部门搜索和勾选业务，支持部门全选、系统全选及清空。每个业务的附加条件使用自身查询定义与默认值，不复用当前浏览事项的非日期条件。授权范围变化会重置面板，服务端再次核验所有事项。

提交先完成整批条件、日期、执行能力、授权及登录状态校验，再以一个SQLite事务创建全部独立任务。创建接口立即返回任务组ID及子任务ID，不等待业务执行。每个子任务保存日期与完整查询条件快照；之后修改页面不会影响已排队任务。脱贫人员仍按原列表查询，选择日期仅记录到任务，其他事项各自使用原来的日期口径。

## 调度

- `guangdong-hrss` 与 `shenzhen-integrated-services` 的远端任务各自最多运行一项，两个系统可以同时运行。
- 其他系统受应用总并发上限控制，默认2项。等待系统串行名额的任务保持queued，不占全局槽，也不会阻挡其他系统。
- 所有初始任务先保存，再交给调度器；取消等待任务不发源站请求，前项失败不阻塞后续任务。
- 同系统、同事项、同条件的活动任务在注册层同步防重，覆盖单项与批量竞争；任务完成后可以再次回流。
- 会话失效时暂停该系统待执行的远端任务，其他系统和本地操作继续。重新识别到已登录后恢复；实际执行前仍复核授权与登录状态。
- 人社没有固定请求等待间隔，沿用串行接口、60秒单次超时、最多5次尝试及耗尽后跳过并保留缺项提示的规则。

深圳一体化当前事项目录尚未实现查询接口，因此提交前会说明无法执行，不生成必败任务；串行策略已经接入，可由后续查询实现直接沿用。

## 任务与数据

任务的metadata使用 `returnBatchId`、`returnBatchOrder`、`returnBatchSize`、`returnFingerprint` 及 `returnContext` 关联任务组。每个事项仍有独立输出批次、进度、结果和导出入口；任务组用于浏览、取消等待项和失败重试，不合并不同业务的表格。

任务中心可从历史任务的“查看任务组”返回整组，按当前授权范围展示统计。取消等待只作用于仍queued的任务；失败重试只创建失败事项的新任务组，沿用原日期快照，保留旧历史。应用中断后沿用现有恢复机制将未完成任务标为失败，可从任务组重试，不会默默重跑。

## 验证

采用真实SQLite、受控执行Promise和隔离Electron页面验证事务创建、日期冻结、额外条件、授权变化、活动任务防重、两系统独立串行、全局并发、取消、会话暂停恢复、状态写入失败、失败项重试、跨业务数据导航和迟到轮询丢弃。界面覆盖1024及760宽度、键盘焦点、错误提示、搜索与全选；隔离界面测试阻断HTTP/HTTPS，不调用真实业务接口。
