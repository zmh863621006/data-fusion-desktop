# 安装窗口交接与离线启动补查

2026-11-27根据用户反馈排查Windows安装窗口重叠，以及麒麟首次打开没有更新、手动检查后才更新的情况。本次修正源码及本地测试，不发布安装包或OSS业务清单。

## Windows通用安装器

通用包是双层NSIS。外层`resources/nsis-universal.nsi`检测64位Windows版本，选择现代或Win7组件，提取到`$PLUGINSDIR`，再用`ExecWait`启动并等待实际安装器。旧逻辑的`AutoCloseWindow`要等整个外层Section结束才关闭窗口，因此正式安装器已经显示时，前置进度窗口仍持续可见；它并不是还在检测环境。

修正为提取成功后、启动实际安装器前执行`HideWindow`。只隐藏前置窗口，后台引导进程继续等待，不能提前退出并清理仍在使用的安装组件。实际安装器结束或取消后，外层返回其原退出码；启动失败时非静默安装显示明确提示，静默安装保留失败码23。`/S`和`/D`继续作为参数传给固定本地程序，不引入命令解释器，也不改变随包图形和数据库组件。

`node scripts/verify-universal-dispatch.mjs`的7个真实NSIS微型场景通过。Win32 `IsWindowVisible`证实可见交接后外层隐藏、子安装窗口可见；`OpenProcess`和`WaitForSingleObject`证实父进程仍等待，提取文件保留。测试覆盖中文及特殊字符安装路径、静默、取消1602、正常返回42、启动失败23、不支持系统87。Win7选择分支在现代宿主替换检测条件模拟，没有运行真实应用安装器或宣称Win7系统实机安装验收。产品隔离4项测试也通过。

本地证据：`.tmp/universal-handoff-20261127/window-lifecycle.json`及`private/deploy/universal-1.0.25/wrapper-dispatch.json`。

## 麒麟启动检查

已只读解析本地最终海思990基础DEB内部`app.asar`：入口为`business-bootstrap.cjs`，包含启动更新器、目标通道与完整性元数据，桌面入口经兼容启动脚本设置kirin990变体。不能据用户看到基础版本1.1.0，就认定没有ASAR更新入口。

固定启动器检查清单的超时是3000ms；未确认新版且本地版本校验通过时，可按既有离线策略进入应用。手动检查使用默认15000ms。原业务层`StartupBusinessUpdates.start()`没有动作，因而离线进入后不会自动补查。这是一个能解释“启动未更新、手动检查成功”的代码缺口；现场那一次是否真的超时，仍须对应通道的`startup.jsonl`证据，不能仅凭现象认定。

修正业务层：只有冷启动走了离线回退时，启动后10秒自动补查一次，复用原签名、目标、下载及完整性校验。手动在线检查已成功则取消补查；手动检查失败或仍离线则保留这一机会；有在途请求时先等待它结束，不并发重复下载。失败不循环重试、不产生未处理拒绝。退出会取消定时和在途工作并等待结束。

后台准备好新版后显示可重启更新，下一次启动使用已准备的版本；本轮不改变保存会话、运行任务繁忙时禁止重启等已有规则，不在回流中强制退出。固定基础壳及其3秒冷启动上限未改，这个补查修复可由新的业务ASAR交付。Windows前置窗口隐藏则属于安装器修复，须重新构建安装包才生效，业务ASAR不能改写用户已下载的安装器。

补查控制器18项合成测试通过，包括离线定时、手动成功取消、失败保留、并发合并、失败不循环及退出取消等待。没有伪造离线状态为在线成功；既有pending强制启动校验保持原规则。
