# 真实业务系统接入检查表

每接一个真实系统，都建立 `docs/systems/<system-id>/`，禁止直接在公共核心里写系统特例。

## 1. 基础信息
- 系统名称、模块 ID、环境地址
- 用户可合法访问的业务范围
- 登录方式：账号密码 / 短信 / 扫码 / SSO / 浏览器跳转
- 是否存在验证码、设备校验、二次认证

## 2. 登录与会话
- 登录入口和跳转链路
- 登录成功判断依据
- Token 来源与字段名
- Cookie 名称、Domain、Path、SameSite
- CSRF 参数
- Header 规则
- Token/Cookie 有效期
- 刷新方式
- 失效响应码/业务码
- Logout 行为

原则：只复用当前用户正常登录产生的会话，不绕过认证，不扩大账号权限。

## 3. 业务事项
每个事项记录：
- matterId / 名称
- 查询条件 Schema
- 默认条件
- 时间范围限制
- 条件联动
- 列表接口
- HTTP Method
- 请求参数和分页参数
- 排序规则
- 响应字段
- 详情接口
- 状态枚举
- 唯一业务键

## 4. 数据同步
必须确认：
- 唯一键是否稳定
- 哪些字段变化需要产生历史版本
- 未办结状态集合
- 已办结状态集合
- 推荐回查窗口
- 是否可能出现补录、撤回、重新受理
- 是否可能删除/作废记录

## 5. 性能与保护
- 原系统分页上限
- 合理请求间隔
- 是否有明确限流响应
- 超时策略
- 失败重试上限
- 禁止无边界并发

## 6. 验收
- 未登录无法查询
- 会话失效可识别
- 查询条件与原系统一致
- 页数/总数一致
- 唯一键验证
- 新增/更新/无变化正确
- 状态历史正确
- 本地导出正确
- 业务数据未上传到产品服务器
