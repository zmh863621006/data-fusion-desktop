# 测试、发布与质量基线

## 1. 测试分层

### Core 单元测试
重点覆盖：
- 唯一键生成
- 新增/更新/无变化判断
- 历史版本写入
- 查询 Schema 校验
- 分页边界
- 请求重试和取消
- License 签名校验
- 插件 Manifest 校验

### Plugin 合约测试
每个真实系统插件必须通过统一合约：
- 未登录时拒绝查询
- 登录状态可读取
- Session 失效可识别
- matterId 唯一
- uniqueKey 非空
- Query Schema 可序列化
- 列表查询返回标准 QueryPage

### 集成测试
使用 Mock 插件验证：
密钥状态 → 系统登录 → 条件查询 → 多页查询 → Sync Preview → Commit → 历史版本 → 导出。

### 手工验收
真实业务系统上线前必须对照原系统抽样验证总数、分页、字段、状态、详情和去重结果。

### 原系统标签与三级菜单回归

运行 `npm run test:source-tabs`，会构建程序并使用独立的临时 Electron 配置、本机 HTTP 测试页进行验证，不连接真实业务系统、不读取正式账号。覆盖：系统/部门菜单折叠，五个系统标签同时保留，切换后原页地址、筛选条件和会话不变，工作台状态保留，账号自动填入（验证码留空），单独关闭标签，以及 1180px 窗口布局。

`npm test` 同时覆盖标签销毁、页面加载异常、来源限制、地址凭据隐藏和浏览器会话同步。真实账号的登录、验证码、SSO 跳转及登录后的接口权限仍需在各业务系统中验收；本地测试通过不代表真实登录已完成。

交互约定：部门默认收起；点击工作台或侧栏只隐藏原系统页，不刷新、不销毁；再次登录已打开的系统会激活已有标签；点击标签的 × 只关闭该页面，不退出会话。保存账号后在原系统页面完成登录，已登录的页面不会被重置，切换账号需先在原系统退出登录。程序退出后不恢复之前的页面位置。

### 全页面外观与交互回归

运行 `npm run test:ui`，依次构建并检查桌面端和管理后台，也可以分别运行 `npm run test:ui:desktop` 与 `npm run test:ui:admin`。

- 桌面端：1440×900、1180×720 两个尺寸，覆盖激活、工作台、5 个系统、可折叠三级菜单、查询与同步、任务及准确批次跳转、本地数据与历史版本、组件、设置、隐藏诊断、独立工具授权和 31 字段原文核对。
- 弹窗：验证 `dialog` 语义、焦点移入、Tab 环绕、Escape 关闭；记录修改仍需显式保存，放弃未保存修改需确认。
- 后台：1440、1180、600 三档宽度，覆盖登录、全部 9 个管理页面、核心表单与抽屉、企业依据页签、账号安全页签和侧栏折叠。
- 检查文档及主内容横向溢出、弹窗边界、浏览器错误；截图与 JSON 报告写入唯一的 `.tmp/ui-redesign-*` 和 `.tmp/admin-ui-redesign-*` 目录，不覆盖已有截图。

两套回归均使用独立临时 Electron 配置与虚构接口数据，阻断外网，不读取正式凭据、业务数据库或生产后台。桌面测试因 Windows 隐藏窗口截图兼容性，仅在截图时短暂非激活显示自己的测试窗口，再使用 Chromium 截图并隐藏，不操作用户窗口。测试结束清理临时配置，保留报告与截图。

这些测试证明界面与交互回归，不等同于真实政务系统联网验收，也不会发布云端后台。视觉调整不改变 Cookie/session 持久化、授权范围、安全校验、字段提取规则或导出缺项标红规则。

## 2. CI
当前仓库使用 GitHub Actions Windows Runner：
- npm install
- npm run typecheck
- npm run build

增加 lockfile 后改为 npm ci 并启用 npm cache。

## 3. 版本规范
主程序使用 SemVer：`MAJOR.MINOR.PATCH`。
插件独立版本，不与主程序强绑定。

建议：
- Patch：Bug 修复，不改变插件协议
- Minor：向后兼容的新能力
- Major：插件协议或本地数据库存在破坏性变化

## 4. 发布通道
后续预留：
- internal：开发/内部验证
- beta：少量业务人员试用
- stable：正式发布

## 5. 数据库迁移
任何数据库结构变化只能通过 migration 完成，禁止启动时临时修改表结构。
迁移规则：
- version 单调递增
- 已发布 migration 不修改
- 新增 migration 完成后再升级应用代码依赖
- 迁移失败必须阻止应用继续写业务数据

## 6. 程序发布

业务系统组件随主程序统一打包。更新流程：获取签名清单 → 下载 → 校验摘要和签名 → 备份当前版本 → 安装 → 健康检查；失败自动回滚。离线设备使用相同签名安装包人工更新。

## 7. 日志要求
日志不得记录：
- 密码
- 完整 Token
- 完整 Cookie
- 短信验证码
- 身份认证敏感参数

允许记录脱敏后的系统 ID、事项 ID、HTTP 状态、业务错误码、耗时、分页信息和任务 ID。

## 8. Definition of Done
一个功能被视为完成至少需要：
- 类型检查通过
- 构建通过
- 核心异常路径有处理
- 不向 Renderer 泄露认证材料
- 不把业务数据发送到产品服务器
- 文档与接口定义同步更新
