# 深圳一体化登录入口核对

2026-11-27根据用户确认，将深圳市一体化经办平台的登录入口改为 `https://61.144.226.148:8001/cas/login`，不再把 `/TRANS/zhsl/home` 当成登录地址。系统仍使用独立持久浏览器分区，保留原站标签页，由原网页处理登录及跳转。源码提交为 `0ff88ab`，修改已进入本地1.1.13通用测试包，未发布自动更新。

两份补充HAR分别记录登录首页和切换账号密码页面。CAS入口先显示密钥验证页，通过本机证书驱动探测及证书列表接口处理密钥；账号密码页面当前分支将密码进行Base64处理后再以SM2加密提交，备用分支才使用MD5。助手沿用原站页面，不自行重放这些登录操作。

这些HAR没有真正提交账号密码后的登录成功跳转、业务首页、只读身份接口或完整Cookie记录。`/cas/getIsOpenNationalEn` 仅提供登录前加密配置，不能作为登录成功证据。因此本轮不新增猜测式登录检测；需要成功首页及只读身份接口的抓包，才能可靠判断会话有效、失效及恢复后的首页入口。当前已有Cookie也只表示待验证，不显示为已登录。

相关目录及原系统标签页回归测试、类型检查通过；最终安装包中两个Windows内核均核对包含CAS地址。仅离线分析HAR，没有向该系统提交账号密码或调用业务接口，原始凭据不进入源码、日志或Git。

## 现场加载失败与1.1.14修复

用户现场日志明确为 `ERR_CERT_COMMON_NAME_INVALID`（-200）。隔离Electron44访问同一CAS入口复现相同错误：服务器叶证书SAN覆盖 `*.sz.gov.cn`、`sz.gov.cn`，不包含访问IP。正常浏览器能够进入PIN页面且地址栏显示证书风险，与现场日志一致。最初Node握手还遇到旧式协商错误；Electron的实际阻断原因是证书名称不匹配，不能把Node的协商差异当作客户端故障原因。

已通过公共CA根验证该叶证书的链，并对 `sz.gov.cn` 进行DNS SAN校验；核对SHA256为 `FC:8E:CF:8F:96:4F:63:01:62:99:FC:DC:0D:8B:E0:4D:FD:6D:93:C0:F1:3D:91:73:DC:3B:B8:10:25:B4:21:46`。这一步仅做TLS握手，未发送HTTP业务请求、账号或密码。Node探测所用兼容选项不进入应用，也不改变应用的TLS协议配置。

源码提交 `ab579bc` 在原系统WebContents证书事件中加入明确例外，仅允许系统 `shenzhen-integrated-services`、分区 `persist:shenzhen-integrated-services`、完整HTTPS源地址 `https://61.144.226.148:8001`，并要求证书DER重算指纹、SAN及有效期都匹配。仅处理名称不匹配，其他来源、端口、证书变更、过期或撤销等错误不予放行。没有关闭全局证书检查，也没有修改Windows证书库。证书于2026-12-12到期；原站更新证书后需重新核对并通过受审查的代码更新调整指纹，不能从现场返回值自动学习信任。
