# 统一企业信息管理

## 范围与原项目依据

本模块管理业务主体信息，不是客户/授权单位管理。政务综合信息、大件运输、网约车车证及卫健工具共用企业库。

- `D:/code/shenzhenRS/ruoyi-system/src/main/java/com/ruoyi/rs/service/impl/TZwzhServiceImpl.java`：政务入库按企业名称查 `t_qyxx`，无记录时登记待查询。
- 同项目 `pyDecode/qyxx_sync.py`、`OpenApiController.java`：企业查询脚本调用阿里云，更新企业库及政务记录。
- `D:/code/collection-system/zzkj-traffic/src/main/java/com/zzkj/traffic/service/impl/TrafficServiceImpl.java` 与 `zzkj-OnlineCar/.../OnlinecarServiceImpl.java`：先按名称查 Redis，未命中时查询阿里云，填法人。
- `AliQueryEtnUtils.java`：`GET https://slycompany.market.alicloudapi.com/business2/get?keyword=...`，Authorization 使用 APPCODE，映射 `data.data.companyName / creditNo / legalPerson`。

没有复用原项目硬编码的密钥；没有导入、修改原项目数据库。本轮使用模拟供应商验证，未调用真实付费接口，真实供应商的信用代码 keyword 支持及业务错误码仍需部署后做小范围验收。

## 查询及匹配规则

1. 原系统已经提供法人及有效统一信用代码时，不请求后台；大件/网约车同一条本地台账已补齐的字段先复用，只补源数据空白。仍缺字段才上传企业名称、可用统一信用代码；政务兼容 `xkXdrMc/qymc/applyer` 和 `xkXdrShxym/xydm/cardNumber`。自然人不查询，身份证号不上传为企业查询词。
2. 政务、网约车、卫健先按标准名称/已确认别名精确查企业库，再复用有效信用代码对应的已核实资料；多企业同名、代码矛盾进入待核对。大件运输有有效代码时优先且仅按代码匹配企业库，没有有效代码才按名称兜底。
3. 按 2026-10-20 用户确认，后台无资料或资料缺项、付费查询已配置并开启时，自动查询阿里云并持久化结果，等待返回后才保存桌面回流台账及批次快照。开关关闭或未配置时保留明确原因，不静默宣称补全成功。后台仍支持运营人员一次最多 20 家的手动补全。
4. 政务、网约车、卫健付费查询先名称，仅空结果才以有效代码兜底；每家每轮最多两次请求。大件运输有有效代码时仅以该代码查询阿里云，未命中不按名称猜企业；无有效代码才按名称查询。网络、HTTP/供应商业务异常不进行代码兜底，也不误标名称错误。
5. 统一代码校验长度、字符集和校验位。名称查询返回不同名称且没有相符的有效代码作证时需人工核对；代码查询必须返回同一码。
6. 企业以代码唯一存储；原始名称和代码留在查询记录中，关联到同一企业即形成可复用别名。
7. 非空手工业务字段不直接覆盖；缺项查询期间，仍由补全管理的字段可按后台资料更新。完整记录不为刷新资料额外发请求。原始 `applyer/cardNumber` 不修改。业务行保留 `enterpriseEnrichment`，包含原值、写入值、身份输入、来源与时间。

## 后台操作

“企业信息”支持分页筛选、登记、批量补全、人工修正和依据查看（最近 100 条；全量历史保留数据库）。状态：待查询、已补全、缺法人、未查到、查询异常、待核对。已补全资料直接复用，待核对必须人工处理。

只有超级管理员能开启/关闭付费查询；运营人员可登记、修正、在已开启时执行补全；只读用户无写权限。云接口最多 4 并发，每分钟最多 240 个关键字，结果/未命中持久缓存 24 小时，错误冷却 15 分钟；同关键字和同企业的在途请求去重。关闭开关停止后续企业，不能撤销已发出的请求。自动查询返回时重新核对人工修正，避免异步覆盖。

页面显示查询进度及错误原因，人工修正保留修改前后值和操作账号。后台停机后未完成批次不会自动继续扣费，可手动重新选择；错误不会无限重试。

## 配置与部署

- 后台进程环境变量 `ALIYUN_ENTERPRISE_APPCODE`：只在服务端配置，不进入页面、桌面安装包、日志或仓库。新增 SQLite 表使用增量 `CREATE TABLE IF NOT EXISTS`；部署前备份数据库。
- 新库付费查询默认关闭；配置密钥并重启后台后，由管理员在企业页面开启。
- 桌面进程环境变量 `DATA_FUSION_ENTERPRISE_URL=https://实际后台域名/api/enterprises/resolve`：必须 HTTPS；仅本机 localhost/127.0.0.1/::1 允许 HTTP 测试。不配置则不发送企业数据。
- 桌面需有效、绑定当前设备且由该后台签发的许可证。接口校验签名及数据库内客户、设备、系统、事项授权；本机开发授权无签名，不自动绕过鉴权。离线证书需要联网才能使用本功能。
- `/api/enterprises/resolve` 按授权查库并在缺项时自动触发后台付费查询；不开启开关则只查库。每批最多 100 家，每设备每分钟最多 5000 项；桌面每 4 家一批、单批最长 60 秒、去重并缓存 30 秒。后续批失败不丢弃先前批次已完成的结果。卫健工具按工具授权校验，不要求业务系统授权。
- 数据库新增 `enterprise_provider_queries` 表保存关键字级冷却和结果缓存，使用 `CREATE TABLE IF NOT EXISTS` 加法迁移，不改变现有企业、客户、授权和设备。
- `enterprise_resolution_queries` 以 `(request_id,strategy)` 保存名称优先/代码优先的执行冷却；查询策略按本次授权系统决定，不使用首次登记的 `source_system`。同一请求不同策略串行、结果快照隔离；全局供应商关键词缓存/限流共享。旧 `review` 不自动解除。

## 大件运输办件信用代码补充（2026-10-20）

证件列表的惠州编号、办理日期筛选及原有字段映射不变。先完成证件筛选、重复编号检查，再对范围内每条证件调用 `POST /gddj/api/approve/permission/selectRequest`，完整 `reqNo` 查询（页大小10，其他筛选空，最多100条安全上限），使用现有业务 Token 和 ApplicationId=3。分页总数、页码及标识需一致。

客户端严格筛选返回 `reqNo` 与证件编号完全一致的办件，唯一匹配且企业名称一致（忽略空白、中英文括号差异）时，从 `transportCreditCode` 取有效统一代码，经过字符和校验位检查；不从经办人取法人。信用代码保留原系统来源，缺法人再请求后台企业库/阿里云，回流保存前等待补全结果。

零匹配、缺代码、无效代码或临时接口错误保留证件行和明确原因；有其他有效代码则按代码补全，没有才名称兜底。多匹配、企业名称矛盾或已有有效代码冲突暂停该行自动补全，保留已有值，并在列表/导出标红提示。会话失效、登录切换和任务取消中止整次回流，不保存半批。

`oversizeApplicationEnrichment` 仅保存接口路径、申请编号、匹配状态/原因、查询时间、办件标识、企业名称及通过检查的信用代码/字段来源。详情页可查看依据；不保存上游原始响应、Token、经办人身份证/手机等。本次链路对新回流生效，旧批次直接导出只沿用既有快照及企业补全；需要办件来源代码的历史记录请按原日期重新回流。

## 回填时机和边界

回流保存前、同步预览时接入补全。导出前再检查缺项，已完整记录不再次请求后台；查看本地记录/回流批次时也可补充仍缺的企业字段，并保存本地版本。卫健工具的补全值及来源单独留存，原 Word 和首次提取值不改；不是后台直接连接桌面数据库，也不会在桌面关闭时推送数据。

比对旧 JSON 后条件更新，防止迟到结果覆盖用户新编辑。历史批次只更新与旧快照一致的行；业务唯一键不变。企业补全不改变本地业务排序时间，另有补全时间与版本依据。导出先固定记录范围再补全，避免筛选字段变化造成翻页漏记录。

后台不可用时保留原始业务数据，断网重跑保留已获取的补全信息。自然人不查询企业接口。企业名称修正不推断修改许可内容、案件名称等业务文本；补齐企业字段也不代表政务其他字段已齐全，`fillStatus` 仍按原有全部必填字段计算。

阿里云接口目前只取标准名称、信用代码、法人姓名，不补法人身份证号。从业人员自然人及普通市场准入查询不接入企业补全。真实付费接口的剩余额度和供应商实际返回需以实际业务使用验证，测试不主动消耗付费额度。
