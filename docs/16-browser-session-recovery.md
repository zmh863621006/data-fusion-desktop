# 原系统会话持久化和首页恢复

## 使用体验

每个系统独立保存会话。关闭应用/关闭原系统标签页不等于退出登录；再次启动后，只恢复已保存且验证有效、在当前授权范围内的系统首页标签页。不自动提交账号密码，不代替用户完成验证码，不延长服务端会话有效期。

- 已验证：显示“业务系统已登录”，恢复首页标签页，允许回流。
- 网络超时、服务端故障、响应无法确认：显示“会话已保留，暂时无法验证”，不删除快照、不误判为登录成功；后续自动检测在 5 秒短缓存到期后重试。
- 明确 401/403、已知登录重定向或明确未登录响应：显示失效，删除恢复快照，等待用户重新登录。
- 主动退出：关闭对应标签页，执行原退出流程并清除该系统快照；其他系统和账号密码配置不受影响。
- 关闭/重开后仍需原系统认可凭据；不能保证永久免登录，也不能绕过服务端踢下线。

首次升级只能恢复原浏览器仍保有的登录信息；旧版本没有持久化的内存 Token 和政务 sid 无法凭空找回。必要时先正常登录一次以建立新快照，此后才可验证跨重启恢复。

## 保存内容与边界

文件仍为用户配置目录下的 `sessions.secure.json`，新增 `browser-session.v1.<systemId>` 键，兼容已有 `government-info.lid`。每个值整体由 Electron `safeStorage`（Windows 用户账户保护）加密，禁止明文降级；密码仍使用原账号配置仓库。

会话保存与登录验证分离：`unverified` 不再阻止完整凭据快照更新，检测后、页面存储保存及正常关闭时仍捕获最新数据，但不会因此标记已登录。若暂时只读到空 API 凭据，则保留已有完整快照；明确失效、主动退出的保存抑制与代际保护不变。

政务兼容迁移：初始化已从 `government-info.lid` 读到的独立捕获值优先于旧浏览器快照中的 lid；缺少独立值才使用快照 lid，sid 仍从快照恢复，并必须重新验证。2026-09-22 对应用加密存储的只读测试证实：旧快照组合查询 404，独立捕获 lid 与同一 sid 的查询和流程详情均返回 200、解码成功。新增回归覆盖旧 lid 不覆盖新 lid、未验证期间更新凭据后关闭/恢复仍需校验，以及不完整读取不破坏已有完整快照。215 项测试、类型检查与构建通过；真实运行中的应用需重启加载后再验收自动恢复。

每个快照保存：版本、配置的站点 origin、接口凭据、该站点适用的 Cookie，以及同源页面的 sessionStorage。localStorage 由各系统独立的 Chromium `persist:` 分区原生保存，不额外导出所有浏览器数据。

Cookie 恢复保留 domain/path/hostOnly/httpOnly/secure/sameSite/expirationDate；已到期或不属于配置站点的 Cookie 不恢复。没有 expirationDate 的 Cookie 仍按会话 Cookie 恢复，不伪造更长有效期。各分区不混用，API 凭据及恢复地址不通过 IPC 传给工作台。

sessionStorage 仅从配置同源页面读取，定时、页面加载完成及正常退出前保存。重开标签页时填入缺失项，再加载已配置首页；不覆盖新页面已写入的值。跨域 SSO/第三方页面的 sessionStorage 不抓取。日志只记录系统 ID 和安全提示，不输出凭据、Cookie 值或页面存储值。

## 启动验证接口

| 系统 | 验证方式 | 成功依据 |
| --- | --- | --- |
| 市场准入 | `POST /approve/sys/login/getCurrentUser.do` | 完整当前用户信息 |
| 政务综合 | 现有 `ecs_searchAll` RPC，沿用查询条件，pageNum=1、pageSize=1，不再添加虚构流水号 | 可解析的 result 数组，无错误字段；不导出、不读取详情 |
| 运输从业人员 | 现有网关 `007400100021`，当天日期、Page=1、Rows=1 | 成功业务状态及 items/totalcount 结构 |
| 大件运输 | `POST /bis/business/licRequestProvincial/list`，当天日期、pageSize=1 | rows/total 及成功码 |
| 网约车车证 | 现有车辆数据接口，当天日期、size=1 | data.records 数组和成功状态 |

后 3 个接口只用于确认授权可读，不保存/输出返回业务记录，不触发回流任务。单次验证带 10 秒超时，同系统合并并发请求；成功缓存 60 秒，未登录/失效/暂不可验证只缓存 5 秒，凭据变化立即重新验证。手动“检测登录并返回工作台”跳过缓存（若已有请求则合并等待），并显示检测中。客户端原有 2 小时标识只是内存调用保护，恢复时不直接沿用为“已登录”：必须先经服务端验证，成功后再启用接口会话。

打开的每个原系统标签页在加载完成后立即检测，主进程每 5 秒继续检测所有已打开标签页，包括后台标签；结果通过仅含状态的 IPC 推送到工作台。检测不依赖前台选中哪个系统，不需要点击“检测登录”按钮。关闭标签页后停止该页检测，旧异步结果不会再推送。

首页：市场准入已登录首页为 `http://19.88.234.125/app/page/frame.html`，未登录时仍沿用原站点入口；政务使用原 Index 页面和恢复的 lid，大件使用 `/bis/index`，车证使用现有站点入口。从业人员未登录入口为 `https://td.gd.gov.cn/cyry/default/index`，已登录首页为 `https://td.gd.gov.cn/cyry/index.html`；API 监听仍独立使用 `/cyry/api/*/DataService*`，不拼接登录页地址。恢复页只允许原站点 origin。启动期间用户已操作工作区或切换标签时，不抢走当前焦点。

已登录后点击“打开原系统”，若现有标签仍停在配置的登录入口，则转到首页；若已经在业务查询/核对页面，则仅切换到该标签，不重新加载或丢弃页面条件。

市场准入登录表单使用专用选择器 `#loginname` / `#loginpwd`。原站密码框初始为 `type="text"`，通常聚焦后才改为密码框；自动填入时先把明确配置的密码框设为 `type="password"`，避免密码明文显示，不抢焦点。只填同源页面中可见、可用的匹配字段，保留用户已修改内容；不填写验证码、不自动提交登录。相关真实 Electron 回归使用合成密码和本地仿真页面，不把用户密码用于测试。

## 可靠性

- 安全仓库串行写入/删除，防止多个系统并发覆盖其他条目。
- 每个系统的快照捕获也串行化，退出登录使用代际标记，拒绝退出前仍在执行的验证重新写回会话。
- 启动验证完成后再次核对当前授权、会话和标签关闭记录；期间已退出、已关闭的系统不会被旧结果重新打开，应用退出开始后也停止自动打开页面。
- 正常关闭窗口/退出应用先等待页面存储、会话快照、Cookie 和安全仓库落盘，再关闭数据库和进程。强杀/掉电不能保证最后一刻的页面内存状态已保存。
- 菜单 IPC 继续显式选择数据字段，不传递新的 sessionRecovery 实现方法。
- 验证不提交真实业务修改，不触发业务回流。
- 验证异常记录系统 ID、错误类型、错误码和网络原因码；不记录原始异常内容、Cookie、Token 或响应数据，相同原因每分钟最多记录一次。

## 自动化验证

2026-09-22 政务真实接口对照：同一组有效凭据，原虚构流水号校验返回 HTTP 200 空响应；改为原列表查询结构、最多一条后返回可解码的 result 数组，验证通过。无效凭据对照返回 HTTP 404，仍为未验证，不误判已登录。返回业务记录仅在内存中检查结构，不保存、不输出。空响应、解码/解析异常、结构不符分别用 EMPTY_RESPONSE、INVALID_RPC_RESPONSE、UNEXPECTED_RESULT 脱敏原因码区分。单元测试、类型检查、构建通过；运行中的旧主进程需重启加载，本次接口验证不等同于跨重启 UI 验收。

- `npm run typecheck`、`npm test`：仓库并发、恢复、失效、离线保留、退出竞争、站点隔离、五种只读验证接口及既有业务回归。
- `npm run test:session-recovery`：使用独立临时配置目录和本地模拟站点，运行多个真实 Electron 进程，验证保存→关闭→恢复首页、sessionStorage/localStorage/会话 Cookie、真实系统加密、断网、失效、退出及退出后重开。
- `npm run test:government-menu`、`npm run test:source-tabs`：回归 18 项政务菜单以及多系统标签页保留，后者结合真实恢复服务验证登录前检查失败→凭据不变登录成功→自动更新、后台标签自动检测，以及手动强制检测。

上述为合成数据/本地模拟站点验证，不代表已对五个真实业务站点完成跨重启实测。新版加载后需在真实会话下验收，尤其确认各站点对无匹配记录的返回结构以及服务端失效响应格式。

2026-09-22 自动检测回归诊断：在独立临时浏览器目录中只读加载现有加密快照，市场准入当前用户接口、大件运输一条列表接口均验证成功，大件返回 HTTP 200、code=0、rows/total。没有读取/输出业务记录，也没有改动正在运行的应用配置。该结果只证明这些保存会话在诊断当时有效，不代表其他系统已验收。`scripts/run-session-diagnostic.mjs` 是显式指定源文件的只读诊断入口，退出后删除它创建的临时配置目录。

早期两次诊断产生的临时目录 `C:\Users\Administrator\AppData\Local\Temp\fusion-session-diagnostic-ARxyMq`、`C:\Users\Administrator\AppData\Local\Temp\fusion-session-diagnostic-VwsaK9` 的清理被环境策略阻止，尚未删除；其中后者包含隔离测试用的受系统保护的会话/密钥容器副本，无原始业务记录或明文凭据输出。可在诊断进程退出后由用户手动删除这两个完整目录，不要删除原应用的 Roaming 配置目录。
