# 麒麟 V10 内部测试版

## 当前范围

- 复用现有业务插件和界面，增加 Linux x86_64、ARM64 的独立打包配置。
- 版本保持 `1.0.20`，安装包名称包含“麒麟测试版”，不上传生产发布后台，不进入 Windows 自动更新。
- Linux 更新检查、下载和安装入口暂不接入 Windows EXE 通道；设置页明确提示使用麒麟包升级。
- Linux 导出固定保存到 Electron 解析的系统“文档”目录下的 `数据融合助手/导出文件`，不写入 `/opt`。
- SQLite、授权和会话继续存放在当前用户的 `data-fusion-desktop` 配置目录，升级程序不覆盖用户数据。
- 密码、会话只接受操作系统加密存储；Linux 默认选择 Secret Service（gnome-libsecret），安装依赖包含 gnome-keyring。拒绝 `basic_text` 和未知后端，保留显式指定其他安全后端的能力。密钥环不可用时提示解锁或手动登录。
- 导出校验弹窗只显示最多四类字段的数量汇总，完整逐条说明保留在 Excel 标红和批注中，避免 GTK 原生弹窗被长列表撑出屏幕。弹窗绑定应用主窗口。
- Linux 导出文件夹链接使用文件管理器 ShowItems 接口定位文件，避免等待 Peony 窗口关闭才返回。
- Windows 的导出目录和更新流程继续沿用原有规则。

## 构建

Linux 构建机安装项目所需 Node.js、npm 和系统打包依赖后执行：

```bash
npm ci
npm run package:linux:x64
npm run package:linux:arm64
```

Electron 运行环境须与目标操作系统、架构匹配。`electron-builder.linux.cjs` 不复用 Windows 的 `electronDist`，不包含 EXE 更新宿主。
若已准备并验证对应 Linux Electron 分发目录，可通过 `DATA_FUSION_LINUX_ELECTRON_DIST` 指定，目录内必须是相应架构的 Linux 二进制。

在 Windows 构建机上也可先生成程序目录，再由具有 `dpkg-deb` 的 Linux 机器组装 DEB：

```text
npm run build
npx electron-builder --config electron-builder.linux.cjs --linux --x64 --dir
node scripts/verify-linux-package.mjs release/1.0.20/kylin/linux-unpacked x64
node scripts/stage-kylin-deb.mjs x64
```

ARM64 对应 `--arm64`、`linux-arm64-unpacked` 和 `stage-kylin-deb.mjs arm64`。
阶段目录由脚本输出；传送时保留目录结构与中文文件名。Linux 上普通文件使用 0644、目录和程序使用 0755，`chrome-sandbox` 使用 04755；通过 `dpkg-deb --root-owner-group` 设置安装文件归属，再组装包。

包内不包含开发密钥、登录凭据、业务数据库或测试授权。`verify-linux-package.mjs` 检查 ELF 架构、应用归档和 Electron 安全开关。

## 安装与系统信任

安装包不包含麒麟厂商签名。受软件来源校验管理的麒麟电脑可能要求管理员对本次内部安装单独授权，或者由单位软件分发机制提供受信任的签名。

若系统明确拒绝安装，先处理具体包的信任授权，不修改全局校验配置，不关闭麒麟安全机制，不用 root 运行应用，不添加 `--no-sandbox`。
完成包安装后可从应用菜单打开“数据融合助手”。离线测试授权必须绑定本机设备并明确限定系统、事项和有效期；不复制 Windows 的加密密码、会话或设备授权文件。
